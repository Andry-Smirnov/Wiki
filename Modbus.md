# Общие принципы
## Настройки
Нерационально забивать трафик постоянным чтением EEPROM для определения его изменений, рационально на стороне контроллера фиксировать изменения в кольцевом списке и уже эту информацию забирать.

## Команды
На стороне контроллера никакой «фильтрации дребезга» для команд быть не должно, пришла команда – контроллер её обработал и обнулил по факту обработки.

Битовые команды можно формировать или командой 0x16 Mask Write Register (в AND сбрасываем только изменяющийся бит, в OR устанавливаем его значение), или командой 0x05 Write Single Coil.

Вышеуказанная схема позволяет спокойно работать даже если источников команд более одного (по разным Ethernet-каналам, сокетам, 485му) – команды просто аккумулируются в регистрах и сбрасываются по факту обработки (не завершения выполнения, а именно обработки, т.е. сразу в цикле после получения команды).

Однако есть вопрос с командами типа больше/меньше.

### Вариант 1.
Три команды – верх передаёт «больше» и «меньше» по переднему фронту нажатия соответствующей клавиши, по заднему передаёт «стоп».

Минус – при потере связи процесс сам не остановится.
### Вариант 2.
Вместо команд «больше» и «меньше» верх передаёт значение, до которого нужно открыть/закрыть механизм.

Плюс – гарантия, что в случае потери связи движение остановится в конкретном положении.

Минус – при отсутствии обратной связи невозможно определить степень открытия/закрытия – разве что косвенно по длительности импульсов управления.
### Вариант 3.
Вместо значения положения из варианта 2 передаётся длительность и полярность импульса, при этом верх может в любой момент передать нулевую длительность и остановить движение.

Плюс – при потере связи движение продолжится не долее переданной длительности, каждый ведущий может передавать свою максимальную длительность воздействия.

Минус – команда перестаёт быть битовой.

## Формат кольцевого списка
Данные добавляются в список в сторону убывания адресов.

Текущая вершина списка доступна в регистре Modbus (это позволяет делать запросы данных только по факту изменения вершины).

Каждая запись содержит чётное число регистров и состоит минимум из четырёх регистров заголовка:

| Смещение регистра | Метка | Описание |
| --- | --- | --- |
| `+0` | id | код события (=0 для обозначения конца списка)|
| `+1` | ms | миллисекунды метки времени (0...999, =0 для обозначения конца списка) |
| `+2`, `+3` | ts | [метка времени](https://www.unixtimestamp.com) события |
| `+4`, `+5` | v1 | опционально – дополнительный параметр 1 ([IEEE-754](https://float.exposed/0x03e80000))|
| `+6`, `+7` | v2 | опционально – дополнительный параметр 2 ([IEEE-754](https://float.exposed/0x34FFFFFF))|
| `+2N+2`, `+2N+3` | vN | опционально – дополнительный параметр N |

Для примера – параметром события в случае изменения настроек EEPROM может быть новое значение, или пара было – стало.

Поскольку значение пары регистров – id = ms = 0 определяет конец списка, значение параметров 0.0 (0x00000000) заменяется на -0.0 (0x80000000), чтобы при обработке кольцевого буфера не возникало путаницы с определением конца списка.
